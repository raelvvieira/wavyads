# WAVY Dashboard, CRM, AI and Charts

## Shared shell

Keep global navigation, workspace/client, identity, command/search, notifications, and theme consistent. Module navigation appears inside the shared shell.

## Performance dashboard

Recommended order: context/period; executive AI summary; 4–6 primary KPIs; investment/results trend; ad → lead → conversation/appointment → sale funnel; campaign table; alerts/opportunities.

Use a horizontal filter island. Keep KPIs and chart panels solid. Let AI insight carry stronger brand expression. Prioritize metrics tied to decisions rather than showing every available metric.

## CRM

Desktop: lead/conversation list 280–360px, flexible solid workspace, collapsible context/AI panel 320–420px, contextual toolbar.

Keep messages, history, and forms solid. Use glass for filters, toolbar, status/responsibility control, quick actions, and AI panel header. In AI analysis, separate evidence, inference, score, and recommendation; link supporting conversation snippets when possible.

## Studio and AI tools

Center the creative canvas, conversation, or workflow. Anchor floating tools to context. Keep generated outputs together for comparison. Expose generation status, version, aspect ratio, model, and actions. Multi-step creation must preserve completed work and allow returning to prior steps.

## Charts

- WAVY orange is primary series, not every series. Use accessible blue, teal, violet, green, and amber companions.
- Line for trends; bars for discrete comparison; stacked bars for composition; funnel only for sequential conversion.
- Start bar axes at zero unless an analytical exception is clearly signaled.
- Limit donut categories and group minor values as Outros.
- Prefer direct labels/useful tooltips; keep grid subtle; state units and period.
- Use pt-BR number/currency formatting where relevant.
- Never use 3D charts or color-only meaning.
- Provide accessible summaries/tables for decision-critical data.
- Design zero, missing, partial, stale, integration-error, and restricted states distinctly.

## Responsive

Wide desktop may use expanded shell. Standard desktop collapses navigation and secondary panels. Tablet/mobile converts details to full-screen sheets, deliberately prioritizes columns, and never depends on hover. Use a bottom island only for 3–5 core destinations.
